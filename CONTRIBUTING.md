# Участие в разработке SnowWars

## Issues и Project

Работа над репозиторием ведётся через GitHub Issues и связанный GitHub Project, а не через
прямые правки без обсуждения. Прежде чем начинать сколь-нибудь значимую работу (новая
функциональность, рефакторинг, исправление неочевидного бага), убедитесь, что для неё есть
issue — если его нет, создайте, кратко описав задачу и область (см. шаблоны в
`.github/ISSUE_TEMPLATE/`).

Небольшие и однозначные правки (опечатки, мелкие фиксы, правки документации без изменения
смысла) можно делать без предварительного issue.

## Работа с Claude Code

Если для работы над репозиторием используется Claude Code, поведение агента описано в
[`CLAUDE.md`](CLAUDE.md). Коротко: главный поток выступает координатором и не редактирует
код напрямую — он распределяет задачи по ролям (сбор фактов о коде, реализация, проверка
результата). Для нетривиальных задач сначала формируется план и согласовывается с
человеком, и только потом идёт реализация; тривиальные правки могут выполняться сразу.
Если вы — человек-контрибьютор, это не меняет процесс работы с GitHub из предыдущего
раздела: issue и обзор PR всё равно нужны, агент лишь помогает с реализацией.

## Коммиты и Pull Request

- Пишите осмысленные commit-сообщения, отражающие суть изменения, а не технические детали
  диффа.
- На момент написания в репозитории нет настроенного CI (`.github/workflows` отсутствует) и
  нет автоматизированных тестов — проверка ведётся вручную, запуском проекта в Godot
  (режимы SERVER/CLIENT/LOCAL, см. [`README.md`](README.md)). Перед тем как открывать PR,
  убедитесь, что проект открывается и запускается в Godot без ошибок для затронутых
  режимов.
- Ссылайтесь на связанный issue в описании PR.
