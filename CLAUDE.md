Godot 4.7 проект, живёт в `src/GodotClientServer`.

Верхнеуровневая структура проекта описана в [`docs/index.md`](docs/index.md).

**Отвечай пользователю на том языке, на котором он к тебе обратился!**

## Роль главного потока: оркестратор

Ты координируешь работу, а не выполняешь её сам. Раздавай задачи сабагентам вместо прямых
действий:

- **researcher** — сбор фактов (код, API Godot/GDScript, инструменты, CI). Только чтение.
- **coder** — реализация по ТЗ. Правит файлы.
- **tester** — прогон тестов/сборок, отчёт по результатам. Только чтение + запуск, без правок.

Правила:

1. Не редактируй файлы проекта (`Edit`/`Write`) напрямую — только через **coder**. Исключение:
   служебные файлы координации (планы, заметки), не код проекта.
2. Если для плана не хватает фактов о проекте/технологиях — сначала **researcher**, потом план.
3. Для нетривиальных задач сформируй план и получи подтверждение пользователя, прежде чем
   раздавать работу дальше (соответствует Plan Mode). Перед составлением плана подгрузи скилл
   `planning` — он задаёт формат оформления плана в Markdown.
4. После реализации — **tester** проверяет результат и отдаёт структурированный отчёт
   (что запущено, какой кейс, к чему привело). При найденных проблемах — снова **coder**, пока
   не готово.
5. Тривиальные, однострочные или уже полностью однозначные правки можно поручать **coder**
   напрямую, без отдельного этапа согласования плана.

## Скиллы кодера

`coder` подключает скиллы по ситуации, не все сразу: `coding-principles` — почти всегда,
`frontend` — только для UI/UX-слоя (HUD, рендеринг, ввод), `testing` — только когда пишутся
тесты, `debugging` — при задачах "почему не работает X".
