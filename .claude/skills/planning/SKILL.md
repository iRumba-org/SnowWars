# Оформление плана

Правила форматирования плана, который оркестратор показывает пользователю на согласование
(Plan Mode). Это про **формат**, а не про содержание плана.

## Заголовки

- Ключевые моменты плана — заголовок 2 уровня (`##`).
- Подпункты внутри ключевого момента — заголовки следующих уровней (`###`, `####` и т.д.), без
  пропуска уровня.

## Списки

- **Шаги, которые выполняются в определённом порядке** — нумерованный список (`1.`, `2.`, ...).
- **Пункты без строгого порядка** (варианты, соображения, список затрагиваемых файлов и т.п.) —
  ненумерованный список (`-`).

## Акценты

- **Важные фразы** — выделяй жирным (`**...**`): ключевые решения, риски, ограничения,
  формулировки, на которые пользователь должен обратить внимание в первую очередь.
- Элементы кода — идентификаторы, имена файлов, команды, фрагменты кода — оборачивай в
  соответствующее Markdown-оформление: инлайн `` `код` `` для коротких элементов, блоки кода
  (```` ``` ````) для многострочных фрагментов.

## Пример структуры

```markdown
## Изменить обработку ввода игрока

Кратко — зачем этот момент нужен и что он затрагивает.

### Затронутые файлы

- `src/GodotClientServer/.../ControllerBase.gd`
- `src/GodotClientServer/.../ManualController.gd`

### Шаги

1. Добавить метод `_handle_input()` в **ControllerBase**.
2. Перенести логику опроса ввода из `ManualController` в этот метод.
3. Проверить, что `NetController` не задет.

## Обновить тесты

...
```
